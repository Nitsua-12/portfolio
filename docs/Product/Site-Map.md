# Site Map & Information Architecture

Five pages, deliberately small. Per [[../Vision/Project-Vision|Project Vision]] and the master brief's "reward curiosity, don't dump everything on one page" principle — depth lives on the case-study pages, not in homepage sprawl.

```
/                    Home — live scene-generator hero, positioning line, entry points
/projects            Projects index — both case studies, one paragraph each
/projects/synthwave-scene-generator
/projects/shift-swap
/about               Background, AI philosophy, faith statement, what he's looking for
/ai-workflow         Dedicated process page — real Decision Log / Dev Journal excerpts
/contact             Email + LinkedIn, no form
```

## Navigation

Persistent top nav: Home · Projects · AI Workflow · About · Contact. Five items, no dropdowns — matches the "respect the visitor's time" principle from the master brief. No separate "Blog" or "Resume" nav item for v1 (resume can live as a downloadable link on `/about` if Austin wants one, not its own page).

## Progressive disclosure

- Home teases both projects and the AI-workflow story without explaining either in full — just enough to make the click obvious.
- Project index gives the "what and why" in a sentence each; full narrative (technical approach, challenges, screenshots) lives on the individual project pages.
- `/ai-workflow` is where the site's own meta-story lives — this project *is* the AI-workflow case study, so this page can reference this exact vault (`/docs`) as evidence, not just describe a process abstractly.
